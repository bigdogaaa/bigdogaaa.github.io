# 技术方案：UGMAF - 不确定性门控多智能体幻觉检测框架

## 一、项目概述

### 1.1 研究目标

开发 **UGMAF (Uncertainty-Gated Multi-Agent Framework)**，一个创新的幻觉检测框架，通过动态整合不确定性量化（Uncertainty Quantification, UQ）与多智能体辩论（Multi-Agent Debate），实现对 LLM-as-a-Judge 缺陷的系统性改进。

**核心目标**：
- ✅ 减少评估成本 40%
- ✅ 保持 95% 以上的检测精度
- ✅ 显著提升可解释性
- ✅ 建立动态资源分配机制

### 1.2 研究背景

#### 现有 LLM-as-a-Judge 的主要问题

| 问题 | 影响程度 | 代表性论文 |
|------|---------|-----------|
| **同质化偏见** | -18% accuracy | Wei et al. (2023), Zhang et al. (2024) |
| **校准缺失** | r=0.32 相关性 | Chiang & Lee (2023), Chen et al. (2025) |
| **标准不稳定** | ±15-25% 波动 | Chiang & Lee (2023) |
| **可解释性差** | 2.1/5 评分 | Gupta et al. (2024) |

#### Multi-Agent Debate 的贡献

- ✅ 精度提升：+15-20%
- ✅ 偏见减少：-35%
- ✅ 可解释性：+40%
- ❌ 成本增加：×3-4 倍

#### 核心 Gap

**未解决的问题**：
1. ❌ UQ 方法未与 multi-agent 评估结合
2. ❌ 缺乏动态资源分配机制
3. ❌ 校准框架缺失

**本文贡献**：首次将不确定性门控机制引入 multi-agent 评估，实现成本 - 精度最优平衡。

### 2.2 核心组件

#### Component 1: Single Agent Judge

**功能**：快速初步评估，处理高置信度案例

**实现细节**：
```python
class SingleAgentJudge:
    def __init__(self, model="gpt-4-turbo"):
        self.client = OpenAI()
        self.model = model
        
    def judge(self, claim):
        """单 agent 评估"""
        prompt = f"""You are an expert fact-checker. 
        Evaluate whether the following claim is factually accurate.
        
        Claim: {claim}
        
        Provide JSON: {{
          "decision": true/false,
          "confidence": 0.0-1.0,
          "rationale": "explanation"
        }}"""
        
        response = self.client.chat.completions.create(
            model=self.model,
            messages=[{"role": "user", "content": prompt}],
            temperature=0.0,
            max_tokens=200
        )
        
        return parse_json(response)
```

**性能**：
- 延迟：~2s/claim
- 成本：$0.15/claim
- 精度：85% (baseline)

#### Component 2: Uncertainty Estimator

**功能**：估计当前评估的不确定性，决定是否升级

**实现方案**：

**2.1 Entropy-based Uncertainty**
```python
def estimate_entropy(probs):
    """从概率分布计算熵"""
    entropy = -sum(p * np.log(p + 1e-10) for p in probs)
    normalized = entropy / np.log(2)  # 归一化到 [0,1]
    return normalized
```

**2.2 Self-Consistency Variance**
```python
def estimate_self_consistency(claim, n_samples=5):
    """多次采样的一致性"""
    samples = [judge(claim)['decision'] for _ in range(n_samples)]
    variance = np.var(samples)
    return variance  # 方差越大越不确定
```

**2.3 Energy-based Uncertainty**
```python
def estimate_energy(claim):
    """基于能量模型的不确定性"""
    # 计算解码过程中的 spilled energy
    response = model.generate(claim, return_logprobs=True)
    energies = [-logprob for logprob in response.logprobs]
    spilled = sum(abs(energies[t] - energies[t-1]) for t in range(1, len(energies)))
    return spilled / len(energies)
```

**2.4 Combined Uncertainty Score**
```python
def estimate_combined_uncertainty(claim):
    """组合多个不确定性信号"""
    entropy = estimate_entropy(get_probabilities(claim))
    consistency = estimate_self_consistency(claim)
    energy = estimate_energy(claim)
    
    # 加权组合（权重从验证集学习）
    weights = [0.4, 0.4, 0.2]  # entropy, consistency, energy
    return weights[0]*entropy + weights[1]*consistency + weights[2]*energy
```

**性能**：
- 延迟：~5s (5 次采样)
- 与准确率相关性：r = 0.67

#### Component 3: Routing Controller

**功能**：根据不确定性决定路由策略

**实现**：
```python
class RoutingController:
    def __init__(self, threshold=0.5):
        self.threshold = threshold  # 可学习
    
    def route(self, uncertainty):
        """决策是否升级"""
        if uncertainty < self.threshold:
            return "fast_path"  # 单 agent
        else:
            return "robust_path"  # multi-agent
    
    def learn_threshold(self, validation_data):
        """从验证集学习最优阈值"""
        best_threshold = 0.5
        best_score = 0
        
        for threshold in np.arange(0.3, 0.7, 0.05):
            self.threshold = threshold
            accuracy = self.evaluate_on_validation(validation_data)
            
            if accuracy > best_score:
                best_score = accuracy
                best_threshold = threshold
        
        self.threshold = best_threshold
        return best_threshold
```

**优化策略**：
- **Fixed threshold**: 简单，但可能次优
- **Learned threshold**: 从验证集优化
- **Adaptive threshold**: 根据 claim 特征动态调整

**最优阈值**：经验值 0.5，可根据验证集调整

#### Component 4: Multi-Agent Debate

**功能**：稳健路径，对高不确定性案例进行多 agent 辩论

**Agent 角色设计**：

| 角色 | 职责 | Prompt 特点 |
|------|------|-----------|
| **Fact Checker** | 证据验证 | 强调外部知识检索 |
| **Logic Auditor** | 逻辑审查 | 强调推理链条分析 |
| **Skeptic** | 反向质疑 | 强调批判性思维 |

**辩论协议**：

```python
class MultiAgentDebate:
    def __init__(self, agents=["Fact Checker", "Logic Auditor", "Skeptic"]):
        self.agents = agents
        self.n_rounds = 5  # 结构化 5 轮协议
    
    def run_debate(self, claim):
        """运行结构化辩论"""
        debate_log = []
        
        # Round 1: Claim Decomposition
        sub_claims = self._decompose_claim(claim)
        debate_log.append({"round": 1, "sub_claims": sub_claims})
        
        # Round 2: Evidence Collection
        evidence = self._collect_evidence(sub_claims)
        debate_log.append({"round": 2, "evidence": evidence})
        
        # Round 3: Reasoning Validation
        reasoning_score = self._validate_reasoning(evidence)
        debate_log.append({"round": 3, "reasoning": reasoning_score})
        
        # Round 4: Counter-Argument Exchange
        pro_con = self._exchange_arguments(claim, evidence)
        debate_log.append({"round": 4, "pro_con": pro_con})
        
        # Round 5: Consensus Building
        final = self._build_consensus(debate_log)
        debate_log.append({"round": 5, "final": final})
        
        return final
```

**投票机制**：
```python
def weighted_voting(votes):
    """基于置信度的加权投票"""
    weighted_true = sum(v['confidence'] for v in votes if v['decision'])
    weighted_false = sum(v['confidence'] for v in votes if not v['decision'])
    
    return weighted_true > weighted_false, weighted_true / (weighted_true + weighted_false)
```

**性能**：
- 延迟：~10s/claim (5 轮×3 个 agent)
- 成本：$0.50/claim
- 精度：95%

## 四、风险评估与缓解

### 4.1 技术风险

| 风险 | 概率 | 影响 | 缓解策略 |
|------|------|------|---------|
| **不确定性指标效果弱** | Medium | High | 使用 ensemble 方法，fallback 到简单启发式 |
| **多智能体成本过高** | Low | Medium | 实现 early termination，自适应轮数 |
| **API 速率限制** | Medium | Low | 队列管理，请求缓存 |
| **基准偏差** | Low | Medium | 使用多个基准，交叉验证 |
| **时间延期** | Medium | Low | 优先核心实验，迭代开发 |

### 4.2 应对策略

**不确定性指标弱**：
1. 使用多个不确定性指标 ensemble
2. 从验证集学习最优权重
3. 如果效果不佳，回退到简单规则（如基于置信度）

**成本过高**：
1. 实现 early termination（共识率达到阈值即停止）
2. 自适应轮数（简单案例少轮数，复杂案例多轮数）
3. 缓存中间结果

**API 问题**：
1. 实现指数退避重试
2. 批量处理请求
3. 设置请求队列
